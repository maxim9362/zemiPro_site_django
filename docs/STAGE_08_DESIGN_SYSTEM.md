# ZemiPro — Stage 08.2: общая дизайн-система и компоненты

Статус: VERIFIED / CI SUCCESS (588/588). Подтверждён [GitHub CI #43613466892](https://github.com/maxim9362/zemiPro_site_django/actions/runs/43613466892) на SHA `852c9d1ea2d9cc989369a3178df65875f94bc64b`. Этап 08 в целом не завершён.

## Технологические границы

- Django Templates + CSS + небольшой vanilla JS. React, SPA, новые зависимости, UI-фреймворки, сетевые шрифты не добавляются.
- Существующий static/css/style.css сохраняется как совместимый fallback, новый static/css/design-system.css загружается после него через templates/base.html.
- Базовый экран имеет ссылку пропуска к #main-content; меню доступно с клавиатуры, закрывается по Escape с возвращением фокуса; без JS навигация остаётся видна.
- Учитываются RU/EN/HE, направление RTL для HE, логические отступы, медиа 768/390, prefers-reduced-motion и изоляция смешанного письма.
- Переключение языка/роли и выход остаются POST с существующим CSRF. Показ кабинета определяется active_role; показ ссылки модератора требует perms.moderation.review_complaints и не заменяет серверную проверку.
- Единственный публичный город пилота — Ашдод; старый пункт «Города» сохранён для совместимости маршрутов и тестов Stage02 до ревизии публичного каталога в 08.3.

Системные шрифты без загрузки CDN; кнопки и поля не ниже 42–44 px; система декоративно различает девять штатных состояний заказа: draft, published, in_discussion, assigned, in_progress, completed, cancelled, expired, disputed. Никакие состояния не добавляются в backend.

## Общие шаблоны

| Файл в templates/components/ | Назначение и источник данных |
|---|---|
| site_navigation.html | Гостевые/авторизованные пункты меню, роль, приглашения перейти в кабинет, уведомления |
| service_card.html | Только объекты активного публичного каталога: повторное использование на главной и в каталоге |
| worker_card.html | Только существующая серверная публичная проекция работника; не передавать raw contact/email |
| form_field.html | Обёртка BoundField для форм входа/регистрации, текст подсказки и ошибки |
| flash_messages.html | Общие типы success/error/warning/status в кабинетах |
| empty_state.html | Безопасное экранированное заглавие/описание/ссылка пустого состояния |
| status_badge.html | Презентация существующего localized_status заказа |

Повторно используются существующие классы .btn, .form, .order-card и .category-card. Новые состояния: .ui-alert, .ui-empty-state, .ui-loading и .ui-status. Модальные окна не вводятся без необходимости; доменные действия/permissions не меняются.
