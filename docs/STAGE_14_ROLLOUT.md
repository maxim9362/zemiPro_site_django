# Stage 14.7 — controlled rollout и rollback

## Переключатели

`ZEMIPRO_KNOWLEDGE_QA_ENABLED` и
`ZEMIPRO_KNOWLEDGE_ROLLOUT_METRICS_ENABLED` имеют значение `False` в коде и не
берутся из `.env`. Публичная активация требует отдельного изменения кода,
review, CI и разрешения владельца. Техническая готовность не является GO.

## Наблюдаемость без PII

`KnowledgeDailyMetric` содержит только календарный день, фиксированный тип
knowledge-объекта, его технический ID, событие и суммарное количество. API не
принимает request/user/IP/session/UA/cookie/query/email/phone. Счётчики raw:
они не являются уникальными посетителями, реальными заказами или доказательством
причинной конверсии. Конкурентный increment атомарен в PostgreSQL.

## Безопасный откат

1. Вернуть QA-флаг в `False`: публичные маршруты сразу отвечают 404, записи не
   удаляются и история остаётся доступна только разрешённой модерации.
2. Выключить metrics-флаг: новые события перестают записываться; страницы
   продолжают работать даже при ошибке таблицы счётчиков.
3. Не удалять опубликованные материалы или аудит. Скрывать отдельный материал
   штатным решением модератора.
4. Не откатывать миграцию в production как аварийный переключатель. Reverse
   migration проверяется только на синтетической базе до выпуска.

## Внешние гейты

Реальный пилот 14.4, редакторская RU/EN/HE-проверка, физические устройства,
нагрузка модерации, настоящие жалобы/метрики и письменный owner GO остаются
`PENDING` и не подменяются CI.
