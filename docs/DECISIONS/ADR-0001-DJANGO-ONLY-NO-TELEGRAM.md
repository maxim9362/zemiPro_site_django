# ADR-0001 — Django-only ZemiPro: отказ от Telegram-бота

**Дата решения:** 2026-11-10  
**Статус:** ACCEPTED (решение владельца); реализация удаления legacy-кода отдельно  
**Область:** ZemiPro web/backend, план будущей системы

## Решение

- ZemiPro развивается как **Django + PostgreSQL** платформа с HTML/HTMX и будущим API для web/mobile.
- Существующий Telegram-бот больше не нужен как пользовательский канал, интеграция, резервная подсистема или источник требований к будущему функционалу.
- **Не переносить** aiogram, FSM-диалоги, Telegram-сообщения, Telegram-specific авторизацию и обработчики в Django. Не строить уведомления через Telegram. Не дублировать аккаунты/заказы из бота без отдельного решения по сохранению реальных данных.
- Утверждённые сценарии маркетплейса реализуются на собственных Django-сервисах, независимо от старого Telegram кода.
- Исторический legacy-код остаётся в репозитории до отдельного безопасного решения об удалении после инвентаризации секретов и backup. Существующие ветки и архивные данные не удалять в рамках этого ADR.

## Последствия для работ

- **00.1:** Telegram — только архивный объект инвентаризации; прежние предложения `ADAPT` код бота для runtime считаются `REJECT`; база Django/PSEO проверяется отдельно.
- **00.2:** старые конфиги и токены всё равно проверяются на риск утечки, даже если бот больше не используется.
- **00.3/00.5:** инвентаризация старых данных допустима в целях безопасного хранения; миграция Telegram базы в новую платформу не планируется.
- **03.7 / 07.3 и др.:** ранее предложенная необязательная привязка Telegram или Telegram-уведомления более не входят в целевой функционал. Уточнение `TECHNICAL_SPEC.md`, `DEVELOPMENT_PLAN.md`, `AGENTS.md` и `ROADMAP.md` выполнить синхронно в отдельной документационной правке, не конфликтуя с открытым PR #5.
- Принцип `один этап — одна ветка — один итоговый PR` сохраняется. Codex Cloud — итоговая проверка после завершения этапа 00, как поручил владелец.

## Не меняется

Не меняются безопасность, приватность заказов, RU/HE/EN/RTL, отсутствие платежей на старте, целевые клиентские сценарии, production/Cloudflare/DNS. Удаление legacy кода и секретов требует отдельной подтверждённой операции.
