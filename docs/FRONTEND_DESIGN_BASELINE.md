## Обязательное правило интеграции с Django

1. **Дизайн уже утверждён.** Не предлагать новый визуальный стиль, новый макет, массовую переработку CSS, изменение композиции, навигации, цветов, типографики, карточек или экранов без отдельного решения владельца.
2. Создавать **производные** Django templates/static/HTMX/JavaScript из этих эталонов; исходники в `docs/frontend/approved/` остаются неизменными. При необходимости общие компоненты разрешено извлекать без потери внешнего вида и привычных сценариев.
3. Разрешены **минимальные технически необходимые** изменения производных файлов: подстановка настоящих данных вместо демонстрационных, ссылки на существующие Django URL, формы и CSRF, серверная авторизация/приватность, корректные состояния/ошибки, локализация RU/EN/HE и RTL, доступность, адаптация под размеры экрана, производительность и безопасность.
4. Перед заметным изменением визуального поведения показать причину, ограниченный diff и сравнение «эталон / результат»; **существенное изменение дизайна — только после отдельного согласования владельца**. Не считать необходимость подключения бэкенда разрешением на редизайн.
5. HTML-файлы — **демонстрационные интерактивные прототипы**, а не production-клиент: встроенные имена, отзывы, цены, заказы и сообщения не становятся реальными данными; демонстрационную логику и примеры не переносить как бизнес-истину. Все права и ограничения проверять сервером Django.
6. **Первый публичный пилот — только Ашдод.** Примеры выбора других городов, встречающиеся в макетах, не разрешают расширить реальную географию; адаптированный UI должен учитывать действующий серверный Ashdod-only gate.
7. Перед закрытием этапа 08 — визуальные скриншотные сравнения для мобильного заказчика, мобильного мастера, ПК-заказчика и ПК-мастера, а также функциональные E2E/permission-тесты RU/EN/HE/RTL. Отличия фиксировать в `docs/PROGRESS.md`.

## Границы и порядок работ

- Папка `docs/frontend/approved/` — **архив исходных эталонов**, не каталог исполняемых production-шаблонов; не подключать их напрямую как публичные Django views.
- Добавление этих HTML и документации **не запускает этап 08** и не подтверждает выполнение 08.1–08.7.
- Этап 08 выполняется **после этапа 07** в одной ветке `stage-08-frontend` с одним итоговым PR. Документационный PR, закрепляющий исходные макеты, — отдельная подготовительная запись и не является PR реализации этапа.
- Никакого deployment, изменения production, DNS, VPS, реальной БД или платёжных интеграций.

## Проверка неизменности

Для каждого эталона сверять SHA-256 файла с таблицей выше (например, `sha256sum docs/frontend/approved/*.html`). Если значение меняется — это нарушение базового правила, пока владелец явно не утвердил новую редакцию эталона и её SHA.
