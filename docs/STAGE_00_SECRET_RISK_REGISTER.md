## 2. Защита от повторного добавления

В ветке \`stage-00-audit\` расширены ignore-шаблоны для распространённых локальных секретов, SQLite/DB и контейнеров ключей. Однако \`.gitignore\` **не удаляет уже отслеживаемые** файлы из PSEO и **не чистит Git history**. Текущий PSEO-репозиторий и рабочие данные намеренно не изменялись.

Для будущей приёмки рекомендована локальная проверка секретов по текущему дереву и истории (например, Gitleaks в изолированном окружении), с выводом только путей и классификации, без строк/материалов из секретов. Уровень доступа и запуск согласовать отдельно. Не пытаться проверять действительность чужих ключей через API без явного разрешения.

## 3. Порядок безопасной обработки владельцем (не выполнялся)

1. Определить, какие аккаунты/сервисы используют отслеживаемые конфиги и какие ключи могут быть действующими. Значения не присылать в чат и не публиковать в PR.
2. Сначала создать/проверить резервные копии нужного контента и баз (00.3), закрыть доступ посторонним, проверить разрешения на репозиторий.
3. Отозвать или ротировать **действующие** ключи через соответствующие сервисы; новые значения разместить только в менеджере секретов или переменных окружения, не в Git.
4. Удалить чувствительные файлы **из отслеживания** без стирания нужных локальных копий (например, \`git rm --cached\`, но только после backup и явного согласования), настроить \`.gitignore\` PSEO.
5. Историческое удаление секретов — отдельный план, поскольку rewrite/force-push влияет на все клоны, PR и ссылки. Даже после очистки истории ключи, однажды опубликованные в Git, следует считать раскрытыми и отозвать.
6. После разрешённой ротации выполнить **санитизированный** повторный аудит: итоговые статусы \`PASS/FAIL/SKIP/NOT_RUN\` и список оставшихся блокеров, но не значения ключей.

## 4. Решение по Telegram

По решению владельца от 2026-11-10 Telegram-бот исключён из будущей платформы. Поддержка и миграция его бизнес-логики прекращаются; файлы legacy пока остаются **только для безопасной инвентаризации и последующего контролируемого удаления**, поскольку нельзя допустить потери данных/секретов. Отключение Telegram runtime или удаление каталогов **не производилось**.
