# Stage 14.3 — Публичные экспертные статьи: контракт интерфейса и видимости

> Статус: `CODE_IMPLEMENTED / CI_PENDING` (перед CI). Публичный запуск: `PENDING_GO`.

## Только проверенный публичный снимок

- Новый маршрут `/{ru|en|he}/advice/` и `/{ru|en|he}/advice/<slug>/` работает по `ZEMIPRO_KNOWLEDGE_ARTICLES_ENABLED`. По умолчанию `False`; запросы возвращают **404**, в меню отсутствует ссылка. Для тестов применяется только `override_settings` на изолированной PostgreSQL.
- Все страницы/изображения/поиск/варианты/sitemap-кандидаты вызывают **один** `public_articles()` с фильтрами: `status=published`, `public_content_safe`, не пустые публичные поля, `approved_version=content_version`, опубликованное время, наличие решения модератора типа `approve` именно для текущей версии, подтверждение авторских прав, действующий профиль из `public_worker_queryset()`, активный специалист и категория/услуга, **город профиля только Ashdod**, категория состоит в текущем списке skills. Любой отзыв права, редактирование или снятие с публикации немедленно исключают материал из выдачи.
- В публичные шаблоны передаются **только** `public_title/public_excerpt/public_body` (сырые поля `title/excerpt/body` помечены `defer`), а также `author.public_display_name_snapshot`; нет вывода `User.__str__`, email, контактных полей, исходных медиа, жалоб и истории модерации.
- Публичный JPEG-доступ отдельным GET `/{lang}/advice/images/<id>/` перепроверяет статус публикации всей статьи и совпадение версии одобрения изображения, возвращает `image/jpeg`/`nosniff`/`CSP sandbox`/`no-store`; приватный маршрут автора остаётся закрытым. Контент и подпись проходят проверку при модерации, но **визуальная проверка** PII/прав человека остаётся ручным редакторским гейтом.
- Публичный список содержит только реально опубликованные материалы, категории с опубликованными статьями, поиск только по публичным полям, ограничение строки и устойчивую пагинацию (12/стр.). Неверные фильтры не отражают входные контакты в HTML, а безопасно показывают пустое состояние.
- Язык интерфейса RU/EN/HE, RTL через общий `base.html`, направление текста по **языку содержания**, кросс-языковые ссылки используют фактический языковой URL материала. **Никаких автоматических переводов.** Machine translation (если когда-нибудь отдельно модерационно добавлен) помечается, с переходом на проверенный доступный оригинал; переводы не выдаются за слова автора.
- Связи: доступная публичная анкета специалиста, активная категория и **явное самостоятельное** создание стандартного заказа `marketplace:order_wizard_start`. Чтение статьи не создаёт ни `Order`, ни `Response`, не меняет рейтинг. При включённом флаге только опубликованные статьи допускаются в небольшой блок на профиле мастера. Старый HTML-эталон не изменён.

## SEO-только подготовка — Stage09 НЕ начинать

- Canonical — на проверенную языковую URL статьи; для машинной версии — на опубликованный оригинал, если он доступен. `hreflang` только для отдельно одобренных `original/human` версий, соответствующих реальному контенту. Кодирование Unicode slugs разрешено без изменения старых URL.
- `Article` JSON-LD только по разрешённым снимкам, настоящему публичному имени и датам модерации; нет вымышленного подтверждения лицензии, рейтинга или выполнения заказа; JSON экранируется против `</script>`.
- Жёсткий `seo_noindex=True` на всех Stage14.3 страницах, включая список и поисковые варианты. `sitemap_candidates` — приватный hook **без публичного sitemap endpoint**. Настоящую регистрацию sitemap/robots, канонические legacy URL/редиректы, search console/индексацию и переход Django проводить **только в Stage09** после отдельного разрешения владельца.
- `ZEMIPRO_KNOWLEDGE_QA_ENABLED=False` и `ZEMIPRO_RECOMMENDATION_REQUESTS_ENABLED=False` не меняются.
