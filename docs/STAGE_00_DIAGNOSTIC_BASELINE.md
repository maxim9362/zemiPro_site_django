## 4. Повторение безопасной проверки

В локальном checkout **ветки `stage-00-audit`** с Python 3.12 можно выполнить из корня репозитория (не требуется Django или доступ к БД):

```bash
python scripts/stage00_static_diagnostics.py
python -m unittest discover -s scripts/tests -p "test_*.py" -v
```

По умолчанию программа **печатает JSON в stdout, не записывает отчёт и не читает секретные значения**. Возврат `0` — только статические проверки прошли; это не результат Django-тестов. Результат с `NOT_RUN` не следует трактовать как `PASS`.

Для будущей полной приёмки с Codex (после подготовки всех 00.1–00.6): на **изолированном** checkout/контейнере с **фиктивными данными** и тестовой PostgreSQL проверить зависимости, `manage.py check`, `check --deploy` с безопасными production-like переменными, `makemigrations --check --dry-run`, `migrate --plan`, чистую миграцию и повторный прогон, тесты auth/permissions/concurrency, restore из 00.3 и GSC/URL из 00.4. Перед запуском Django обеспечить, чтобы `.env` и `DB_*` не указывали на production; `load_dotenv()` в `main` прочитывает локальный `.env`. Не выполнять команды на обычном VPS без отдельного разрешения.
